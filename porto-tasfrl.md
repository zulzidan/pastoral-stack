# TASFRL Project Overview

This document summarizes what TASFRL is, what has already been built, the current frontend and backend feature coverage, and what you bring to the table as a contributor.

## What Is TASFRL?

TASFRL is a land management and tribal services platform. It combines:

- Public information and outreach (programs, events, resources, partners, news)
- User onboarding and verification
- Profile and account management
- Land stewardship planning workflows
- Membership, donation, and payment flows
- Admin operations for plans, users, subscribers, and content-linked workflows

In short: TASFRL is not only a marketing site. It is a working service platform with authenticated user journeys, operational tooling, and payment/content integrations.

## What We Have Built So Far

## 1) Public Website and Content Experience

- Multi-page public site (home, about, benefits, gallery, partners, resources, summits, membership, legal/contact pages)
- Dynamic content pages for programs, events, and land-management service detail pages
- Contentful-backed content architecture for news, newsletter content, legal/privacy content, and event-related content
- SEO-supporting route structure including sitemap/robots support and structured content pages

## 2) Authentication and Account Flows

- Email/password login support
- Google OAuth callback/token handling support
- OTP verification and resend verification flows
- Forgot/reset password flows
- Session token handling with cookie-based auth and bearer-token compatibility
- Protected route gating for member areas and admin areas

## 3) User Profile and Onboarding

- Profile completion flow
- Address update and avatar upload/update support
- Password create/update support for account security
- Account deletion endpoint support
- Dedicated account area and dashboard routes for authenticated users

## 4) Land Stewardship / Plan Workflow

- Multi-step plan collection workflow (step-based API support)
- Current plan retrieval and plan listing/detail support
- Plan submit flow and related user linkage logic
- Admin-side plan review, assessment update, and plan statistics endpoints

## 5) Payments and Commercial Flows

- Stripe checkout session creation endpoint
- Stripe webhook handling endpoint
- Success/cancel return routes for checkout outcomes
- Donation-related API route support

## 6) Newsletter and Email Automation

- Newsletter API and subscriber management routes
- Contentful webhook flow for newsletter automation
- Backend-supported subscriber/user retrieval for campaign sending scenarios
- React Email templates and local preview tooling in both frontend and backend environments

## 7) Admin and Operations Tooling

- Admin dashboard data endpoints
- Admin user management endpoints
- Admin subscriber and plan management endpoints
- Admin job application handling endpoints
- Admin backup trigger/listing with secure download-token flow in backend
- Operational docs for deployment, logs, webhook listener flow, and API docs UI

## Frontend Implementation Coverage (Next.js)

The frontend (this repository root) currently includes:

- App Router pages and layouts for public + authenticated areas
- Internal API routes under app/api for:
  - auth/session endpoints
  - profile/account endpoints
  - plan workflow endpoints
  - admin endpoints
  - contentful webhook/config endpoints
  - stripe endpoints
  - contact/newsletter/event routes
- UI system based on Tailwind + shadcn/Radix primitives
- Form validation pattern using React Hook Form + Zod
- SWR usage for client data fetch/caching patterns
- Playwright E2E test scaffolding and test suites

## Backend Implementation Coverage (AdonisJS)

The backend lives in backend/ and currently provides:

- Auth, profile, and account APIs
- OTP and password reset/verification endpoints
- Contact, subscribe, and newsletter-webhook-related routes
- Plans and land-stewardship API endpoints (including step workflow)
- Stripe-related endpoints and handlers
- Admin route group for dashboard, plans, subscribers, users, and job applications
- Backup workflows:
  - POST /admin/backup/send
  - GET /admin/backup/files
  - GET /backups/download/:fileName
- OpenAPI + docs endpoints:
  - GET /openapi.json
  - GET /docs
- Upload serving and deployment-ready operational scripts/docs
